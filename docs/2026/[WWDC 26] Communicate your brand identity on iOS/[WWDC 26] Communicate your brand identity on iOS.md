## 한 줄 요약

이 세션은 iOS의 익숙한 탐색 방식과 시스템 컴포넌트를 유지하면서, 콘텐츠·색상·타이포그래피·아이콘·모션을 통해 앱의 고유한 브랜드 정체성을 표현하는 방법을 실제 앱 사례와 함께 설명한다.

---

## 핵심 요약

Apple은 iOS 앱의 브랜드 표현을 **UI 레이어**와 **콘텐츠 레이어**로 나누어 생각할 것을 권장한다.

1. **UI 레이어**
   - 탭 바, 상단 도구 막대, 메뉴 등 탐색과 동작을 담당
   - 사람들이 이미 익숙한 iOS 컴포넌트와 패턴을 우선 사용
   - 기능적인 요소를 과도하게 사용자화하지 않음

2. **콘텐츠 레이어**
   - 이미지, 영상, 데이터 시각화, 텍스트, 애니메이션 등 앱 고유의 정보
   - 브랜드 정체성을 가장 적극적으로 표현할 수 있는 영역
   - 앱의 목적과 감정적 인상을 전달

3. **브랜드 표현 수단**
   - 색상은 의미와 상태를 전달하도록 절제해 사용
   - 커스텀 서체는 Dynamic Type을 지원
   - 아이콘은 작은 크기에서도 알아볼 수 있어야 함
   - 모션은 콘텐츠 관계와 계층을 설명
   - 로고는 콘텐츠를 방해하지 않는 방식으로 사용

---

# 1. 브랜드와 플랫폼 경험의 균형

브랜딩은 제품을 구분하고 기억하게 만드는 중요한 수단이다. 하지만 웹사이트, 마케팅 자료, 오프라인 매장, 다른 플랫폼의 앱에서 사용한 브랜드 표현을 iOS 앱에 그대로 복제하는 것이 항상 적절한 것은 아니다.

각 매체는 서로 다른 맥락을 가지며, iPhone 사용자는 앱이 다음과 같이 동작하기를 기대한다.

- 익숙한 위치에서 탐색할 수 있음
- 시스템과 일관된 제스처 사용
- 예측 가능한 버튼과 메뉴 동작
- 접근성 설정에 자연스럽게 대응
- iOS의 시각적·상호작용적 언어 준수

앱이 Apple의 기본 앱과 동일하게 보여야 한다는 뜻은 아니다. 운영체제의 익숙한 기반 위에서 앱의 고유한 정체성을 표현하는 것이 핵심이다.

---

# 2. UI 레이어와 콘텐츠 레이어

Liquid Glass가 도입된 iOS 26 이후, 앱 인터페이스는 두 개의 개념적 레이어로 구분할 수 있다.

| 레이어 | 역할 | 대표 요소 |
|---|---|---|
| UI 레이어 | 앱의 전역 탐색과 주요 동작 제공 | 탭 바, 상단 도구 막대, 버튼, 메뉴 |
| 콘텐츠 레이어 | 앱의 고유한 기능과 정보 표현 | 이미지, 영상, 텍스트, 데이터, 일러스트레이션 |

## UI 레이어

UI 레이어는 콘텐츠 위에 떠 있는 탐색과 동작의 기반이다. 사용자가 앱을 이동하고 원하는 기능을 찾도록 돕는다.

이 영역에서는 사람들이 이미 알고 있는 iOS 패턴을 최대한 활용하는 것이 좋다.

- 표준 탭 바
- 표준 도구 막대
- 시스템 버튼 배치
- 시트와 팝오버
- 컨텍스트 메뉴
- 그리드와 그룹화된 테이블

## 콘텐츠 레이어

콘텐츠 레이어는 브랜드를 표현하기 가장 좋은 영역이다.

다음 요소가 포함될 수 있다.

- 제품 이미지
- 전체 화면 영상
- 일러스트레이션
- 데이터 시각화
- 배경과 그래디언트
- 앱의 목소리와 문체
- 전환과 애니메이션

UI 레이어가 사용법을 설명한다면, 콘텐츠 레이어는 앱이 무엇인지와 어떤 감정을 전달하는지를 보여준다.

---

# 3. 컴포넌트

## 표준 컴포넌트를 기반으로 시작하기

표준 컴포넌트는 유연하고 기능적이며, iOS 사용자가 이미 이해하고 있다.

기능적인 작업을 위해 별도의 커스텀 컴포넌트를 만드는 대신 다음을 먼저 검토하는 것이 좋다.

- 표준 목록과 그리드
- 탭 바
- 상단 도구 막대
- 시트
- 메뉴
- 컨텍스트 메뉴
- 시스템 버튼
- 기본 전환

표준 컴포넌트를 사용하면 익숙한 상호작용, 접근성 지원, 시스템 변화 대응, 유지보수 비용 절감이라는 이점이 있다.

## Gentler Streak 사례

Gentler Streak는 장난스러운 일러스트레이션과 자세한 데이터 시각화로 강한 정체성을 보여준다. 하지만 탐색 구조는 네이티브 탭 바와 상단 도구 막대를 사용해 표준 iOS 패턴을 따른다.

## Slack 사례

Slack은 채널 정보를 표시하기 위해 상단 도구 막대를 사용자화했다. 그러나 버튼 크기, 떠 있는 동작의 위치, 팝오버 동작과 전체 구조는 iOS의 언어를 유지한다.

## Moonlitt 사례

Moonlitt의 달 주기 캘린더는 고유한 커스텀 컴포넌트지만 Liquid Glass 배경, 명확한 닫기 동작, 하드웨어 형태와 조화를 이루는 모서리, 단순한 화면 계층을 통해 iOS에 자연스럽게 어울린다.

---

# 4. 커스텀 컴포넌트를 사용할 위치

커스텀 컴포넌트는 제작과 유지보수에 많은 시간이 필요하다. 따라서 다음 영역에 집중하는 것이 좋다.

- 앱 콘텐츠를 특별하게 만드는 부분
- 제품의 핵심 기능
- 경쟁 제품과 구분되는 상호작용
- 사용자에게 가장 큰 영향을 주는 화면
- 표준 컴포넌트로 충분히 표현할 수 없는 경험

반대로 설정 메뉴, 일반적인 목록, 보조 작업 메뉴, 삭제·공유·이동 같은 익숙한 동작은 표준 컴포넌트를 먼저 고려한다.

## 컨텍스트 메뉴

컨텍스트 메뉴는 아이콘, 섹션, 하위 메뉴, 모달 표시, 버튼에서 메뉴로 변하는 애니메이션을 기본으로 제공한다. 기능적인 메뉴를 직접 만들기보다 시스템 컴포넌트를 활용하면 더 네이티브한 경험을 제공할 수 있다.

---

# 5. 콘텐츠

콘텐츠는 앱이 제공하는 정보이며 브랜드 표현의 중심이다.

- 사진과 일러스트레이션
- 영상
- 텍스트
- 데이터 시각화
- 3D 요소
- 배경 색상
- 전환과 모션

중요한 것은 장식이 아니라 명확한 목적을 갖는 것이다.

## Crumbl 사례

Crumbl은 매주 바뀌는 쿠키 맛을 전체 화면 영상으로 보여준다. 영상은 실제 제품과 직접 연결되고, 매주 새로운 내용을 제공해 제품에 대한 감정적 관심을 높인다.

## Moonlitt 사례

Moonlitt은 밤하늘을 연상시키는 가장자리까지 이어지는 색상과 3D 요소를 사용한다. 3D 콘텐츠는 사용자의 위치와 달의 관계를 동적으로 표현하며 앱의 핵심 정보와 직접 연결된다.

---

# 6. 목소리와 문체

브랜드는 시각 요소뿐 아니라 앱에서 사용하는 단어와 문장으로도 전달된다.

앱은 즐겁고 장난스럽거나, 신뢰할 수 있고 안전하거나, 차분하고 전문적인 감정을 목표로 할 수 있다. 버튼 제목, 오류 메시지, 온보딩, 빈 상태, 알림, 도움말, 성공 피드백에서 일관된 목소리를 유지해야 한다.

세션은 UX Writing을 더 자세히 다루는 **“Add personality to your app through UX writing”**도 함께 볼 것을 권한다.

---

# 7. 전환과 애니메이션

사용자는 앱을 정적인 화면 모음으로 경험하지 않는다. 스크롤하고, 탭하고, 화면을 이동하며 브랜드를 경험한다.

## NYT Cooking 사례

NYT Cooking은 레시피 상세 화면에서 댓글을 표시할 때 SwiftUI의 Zoom Transition을 사용한다. 이 전환은 사용자가 누른 대상과 다음 화면의 관계를 설명하고 상호작용을 더 유동적으로 만든다.

## Gentler Streak 사례

Gentler Streak의 월간 요약 화면에서는 스프링 애니메이션으로 활동 데이터를 표현한다. 모션은 화면을 생동감 있게 만들고 계층을 강조하며 중요한 정보에 주의를 집중시킨다.

## 성능의 중요성

로딩이 늦거나 프레임이 떨어지면 브랜드 인상도 나빠진다. 지연된 반응, 끊기는 스크롤, 부드럽지 않은 전환, 늦게 나타나는 콘텐츠는 사용자가 앱을 덜 만족스럽게 느끼게 만든다.

---

# 8. 색상

## 브랜드 색상을 콘텐츠 영역으로 이동하기

iOS 26 이전에는 상단 도구 막대나 탭 바에 단색 브랜드 배경을 넣는 앱이 많았다. 이 방식은 콘텐츠를 위아래에서 감싸며 실제 콘텐츠 영역을 좁게 만들 수 있다.

Liquid Glass 디자인에서는 브랜드 색상을 콘텐츠와 스크롤 영역으로 이동하는 것이 권장된다.

- 콘텐츠가 화면 가장자리까지 확장
- Liquid Glass 컨트롤이 콘텐츠 위에 떠 있음
- Glass가 아래의 브랜드 색상을 동적으로 반영
- 스크롤에 따라 색상이 자연스럽게 이동

## 색상에 의미 부여하기

색상은 다음 목적으로 사용할 수 있다.

- 계층 표현
- 관련 항목 그룹화
- 상호작용 가능한 요소 표시
- 상태 전달
- 피드백
- 선택된 항목 강조
- 새로운 정보 표시

## Slack 사례

Slack은 새로운 정보가 있는 섹션, 읽지 않은 메시지 배지, 새 메시지 작성, 선택된 탭과 주요 동작에만 색상을 사용한다. 색상이 상태와 선택을 설명하기 때문에 사용자가 중요한 부분에 집중할 수 있다.

---

# 9. Dark Mode와 개인 설정

iPhone은 개인적인 기기이며 Dark Mode는 편안함과 필요에 따라 사용자가 지정하는 환경이다.

앱이 Dark Mode를 지원하지 않으면 저조도 환경에서 지나치게 밝거나, 텍스트 대비가 부족하거나, 시스템과 앱 사이에 시각적 단절이 생길 수 있다.

브랜드 색상은 고정된 단일 값이 아니라 Light Mode와 Dark Mode 모두에서 기능하고 의미를 유지하는 체계로 설계해야 한다.

---

# 10. 앱 밖으로 확장되는 색상

브랜드는 앱 내부에만 머물지 않는다. 위젯과 같은 시스템 경험에서도 브랜드를 접하게 된다.

Crumbl의 위젯은 파스텔 색상 팔레트와 제품 이미지를 사용해 한눈에 알아볼 수 있게 한다. 위젯은 앱의 축소판이 아니라 시스템 공간에 맞춰 핵심 정보와 브랜드를 다시 구성한 경험이어야 한다.

---

# 11. 타이포그래피

타이포그래피는 대담함, 우아함, 친근함, 전문성, 전통성, 장난스러움 같은 인상을 전달한다. 하지만 표현보다 기능이 우선되어야 한다.

## Crumbl Sans

Crumbl은 마케팅과 앱의 기억에 남는 순간에 자체 서체인 Crumbl Sans를 사용한다. 특히 쿠키 맛을 보여주는 큰 제목에서 브랜드 성격을 강하게 표현한다.

---

# 12. Dynamic Type

Dynamic Type은 시스템 전반에서 글자 크기를 조절하는 접근성 및 개인 설정 기능이다.

시스템 서체는 Dynamic Type을 기본 지원하지만 커스텀 서체는 직접 지원하고 테스트해야 한다.

Crumbl은 글자 크기가 커질 때 텍스트를 잘라내지 않고 여러 줄로 표시하며, 레이아웃이 콘텐츠 크기에 맞게 확장되도록 구성한다.

Dynamic Type은 텍스트뿐 아니라 탭 아이콘, 탭 레이블, 컨트롤 배치와 탐색 구조에도 영향을 줄 수 있다.

---

# 13. Apple 시스템 서체

San Francisco는 Apple 플랫폼의 시스템 서체이며 150개 이상의 언어를 지원한다.

| 서체 | 특징 |
|---|---|
| SF Pro | Apple 플랫폼의 기본 시스템 서체 |
| SF Compact | 작은 크기에서의 가독성에 최적화 |
| SF Mono | 행과 열 정렬에 적합한 고정폭 서체 |
| New York | 읽기 경험과 그래픽 디스플레이를 위한 세리프 서체 |
| SF Rounded | 부드럽고 친근한 인상을 제공하는 변형 |

Gentler Streak은 시스템 서체의 폭과 SF Rounded 같은 변형을 조합해 고유한 브랜드와 계층을 만든다.

---

# 14. 아이콘

좋은 커스텀 아이콘은 다음 특성을 가진다.

- 작은 크기에서도 식별 가능
- 불필요하게 복잡하지 않음
- 일관된 선 두께
- 앱 전체에서 통일된 스타일
- 각 동작의 목적을 분명히 표현
- 플랫폼의 익숙한 의미를 훼손하지 않음

## NYT Cooking 사례

NYT Cooking은 비교적 날카로운 모서리와 선 중심의 아이콘을 탭 바, 상단 도구 막대, 콘텐츠 내 동작에 일관되게 사용한다.

공유 아이콘은 iOS, Android, Web에서 서로 다른 형태를 사용하면서 각 플랫폼 사용자가 기대하는 공유 패턴을 따른다.

---

# 15. SF Symbols

모든 앱에 커스텀 아이콘이 필요한 것은 아니다.

SF Symbols는 7,000개 이상의 심볼을 제공하며 다음 특성을 가진다.

- 텍스트처럼 동적으로 크기 조절
- 다양한 선 두께
- 접근성 지원
- 현지화 지원
- Apple 플랫폼 전반에서 사용 가능
- 중립적인 시각적 스타일
- Xcode에 직접 통합

앱의 고유한 콘텐츠에는 커스텀 아이콘을 사용하고, 일반적인 시스템 동작에는 SF Symbols를 사용하는 혼합 방식도 가능하다.

# 16. 로고

iOS 앱 안에서는 사용자가 이미 어떤 앱을 사용 중인지 알고 있다. 따라서 화면마다 큰 로고를 반복해서 표시할 필요는 없다.

NYT Cooking은 로고를 홈 탭에만 표시하고 스크롤하면 자연스럽게 사라지도록 구성한다.

브랜딩은 눈에 띄게 반복하기보다 절제되고 방해되지 않는 방식으로 통합할 수 있다.

---

# 17. 사례별 정리

| 앱 | 주요 브랜드 표현 | 유지한 iOS 특성 |
|---|---|---|
| Gentler Streak | 일러스트레이션, 데이터 시각화, 스프링 모션, 서체 변형 | 네이티브 탭 바와 도구 막대 |
| Slack | 제한적인 브랜드 색상, 커스텀 채널 동작 | 익숙한 버튼 크기, 배치, 팝오버 |
| Moonlitt | 달 주기 캘린더, 그래디언트, 3D 콘텐츠 | Liquid Glass, 표준 시트와 컨텍스트 메뉴 |
| Crumbl | 전체 화면 영상, 제품 이미지, Crumbl Sans, 파스텔 위젯 | Dynamic Type 대응과 시스템 구조 |
| NYT Cooking | 커스텀 아이콘, Zoom Transition, 절제된 로고 | 플랫폼별 공유 관습과 익숙한 탐색 |

# 18. 디자인 체크 포인트

- [ ] 앱의 UI 레이어와 콘텐츠 레이어를 구분했는지 확인
- [ ] 탭 바와 도구 막대 같은 전역 탐색에 표준 컴포넌트 사용 검토
- [ ] 커스텀 컴포넌트가 핵심 경험에 실질적인 가치를 주는지 확인
- [ ] 기능적인 메뉴를 직접 만들기 전에 컨텍스트 메뉴 검토
- [ ] 브랜드 콘텐츠가 장식이 아니라 앱의 목적과 연결되는지 확인
- [ ] 문체와 메시지가 앱이 전달하려는 감정에 맞는지 점검
- [ ] 전환과 모션이 콘텐츠 관계와 계층을 설명하는지 확인
- [ ] 애니메이션과 스크롤에서 지연이나 프레임 저하가 없는지 측정
- [ ] 브랜드 색상을 콘텐츠 영역에 배치하는 방식 검토
- [ ] 색상이 상태, 선택, 피드백 등 명확한 의미를 가지는지 확인
- [ ] Light Mode와 Dark Mode 모두에서 색상 체계 테스트
- [ ] 위젯 등 앱 외부 경험에서도 브랜드가 시스템 맥락에 맞는지 검토
- [ ] 커스텀 서체가 Dynamic Type 전 범위를 지원하는지 테스트
- [ ] 큰 접근성 글자 크기에서 텍스트가 잘리거나 겹치지 않는지 확인
- [ ] 시스템 서체 변형으로 필요한 표현이 가능한지 검토
- [ ] 커스텀 아이콘이 작은 크기에서도 식별 가능한지 확인
- [ ] 공유·삭제 등 익숙한 동작은 플랫폼 관습을 따르는지 점검
- [ ] 일반적인 동작에 SF Symbols를 활용할 수 있는지 검토
- [ ] 로고가 콘텐츠를 방해하거나 공간을 과도하게 차지하지 않는지 확인
- [ ] 브랜드 표현이 앱의 익숙한 사용성을 훼손하지 않는지 점검
