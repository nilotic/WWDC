# Design foundations from idea to interface

Design foundations from idea to interface https://developer.apple.com/videos/play/wwdc2025/359/



## ✨ 개요


“ 앱이 ‘ 그냥 잘 된다 ʼ 고 느껴지게 만드는 방법 ” 을 구조 → 내비게이션 → 콘텐츠 → 비주얼의 4 단계로 정리합니

- 다 . 핵심 질문은 세 가지 : 어디에 있나 ? 무엇을 할 수 있나 ? 여기서 어디로 갈 수 있나 ?이 질문에 망설임 없이 답하게 만들면 흐름 (flow) 이 생깁니다 .

- 🎯 핵심 원칙

- 구조 (Information Architecture): 기능 · 워크플로를 모두 적어 본 뒤 , 불필요한 것 제거 · 이름 명확 화 · 자연스러운 묶음으로 단순화해 앱의 목적을 날카롭게 정의 .

- 내비게이션: 탭 바는 섹션 간 이동 전용— 주요 액션 ( 예 : 추가 ) 은 화면 내부 ( 예 : Records) 로 . 탭 수는 최소화하고 , 명확한 라벨 +SF Symbols로 예측 가능성 강화 .

- 콘텐츠 구성: 툴바로 현재 위치 + 화면별 액션을 명료화 . ** 점진적 공개 (Progressive disclosure)** 로 처음엔 꼭 필요한 것만 , 더보기로 확장 . 스캔이 중요한 영역은 List가 Grid 보다 유리 . 대량 항목은 Collection으로 .

- 콘텐츠 그룹핑 패턴: 시간 ( 최근 / 시즌 ), 진행도 ( 미완료 / 이어보기 ), 패턴 ( 연관성 / 유사성 ) 으로 묶어 과부 하를 줄이고 다음 행동을 제안 .

- 비주얼 디자인: 시각적 위계로 시선 흐름을 설계 . 시스템 텍스트 스타일 +Dynamic Type로 다양한 환경에 견고하게 . 이미지 위 텍스트는 그라디언트 / 블러로 가독성 확보 . 일관된 팔레트 / 스타일을 정하 고 , UI 전반엔 시맨틱 컬러를 우선 사용 ( 포인트로만 액센트 컬러 ).



## ✅ 실무 체크리스트


- 핵심 기능 3~4 개만 탭 바로 노출 ( 탭 = 내비 , 액션 =X)

- 각 화면 상단 툴바 타이틀로 맥락 제공 , 액션은 화면별 최소 세트만

- 첫 화면은 그룹 일부만 보여주고 더보기로 확장 ( 점진적 공개 )

- 길이 가변 텍스트 / 다국어 / 큰 글씨에서도 시스템 텍스트 스타일 유지

- 목록은 List, 대량 이미지 / 카드 스크롤은 Collection

- 색상은 시맨틱 컬러 중심 , 자체 팔레트는 일러스트 / 빈 카드 등 한정 적용

- 🛠 흔한 함정 → 해결법

- 첫 진입에 햄버거 메뉴 · 브랜딩만 보임 → 툴바 타이틀 + 핵심 컨텐츠 앵커 배치

- 탭 바에 “ 추가 ” 같은 행동 배치 → 해당 섹션 내부의 플로팅 / 툴바 액션으로 이동

- 2 열 Grid 에 긴 텍스트 → List 템플릿으로 전환해 스캔성 확보

- 영웅 배너에 시선 빨려 들어감 → 텍스트 고정 영역 + 콘트라스트 위계로 재구성

- 제각각 이미지 톤 → 공유 팔레트 / 형태 규칙으로 일관성 부여

- 🍎 iOS 구성요소 활용 팁

- Tab Bar( 내비 전용 ), Toolbar( 제목 + 화면 액션 ), SF Symbols( 익숙함 / 의미 강화 ), List/Collection( 정보 밀도 / 대량 아이템 ), Dynamic Type+ 시스템 텍스트 스타일, 시맨틱 컬러를 기본

- 으로 삼으면 확장과 접근성이 함께 해결됩니다 .
