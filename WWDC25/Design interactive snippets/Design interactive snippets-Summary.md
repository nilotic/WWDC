# Design interactive snippets

Design interactive snippets https://developer.apple.com/videos/play/wwdc2025/281/



## ✨ 개요


Spotlight·Siri· 단축어에서 뜨는 스니펫 (snippet) 을 더 읽기 쉽고 , 바로 행동 가능한 형태로 설계하는 법 을 다룹니다 . 결과 / 확인 두 타입 , 큰 글자 · 간결 레이아웃 , 버튼 · 상태 업데이트 , 음성 다이얼로그 활용이 핵심

입니다 .



## 🧩 스니펫이란 ?


App Intents 가 띄우는 콤팩트 카드형 뷰로 어디서든 호출 가능 (Spotlight, Siri, 단축어 ).

화면 맨 위에 오버레이로 나타나고 확인 · 취소 · 스와이프 시 사라짐 → 맥락 전환 없이 루틴 작업 처리 에 적합 .

🧭 레이아웃 & 가독성 큰 타입 ( 시스템 기본보다 큼 ) 으로 핵심 정보에 시선 집중 .

요소 간 충분한 간격, 일관된 마진(ContainerRelativeShape 로 반응형 여백 ) 유지 .

내용은 340pt 높이 이내로 스크롤 유도 금지 , 자세한 내용은 앱으로 링크.

앱 아이덴티티 기반의 생동감 있는 배경 가능하나 , 거리에서도 읽히는 대비를 반드시 확보 .

🖱 상호작용 (Interactivity)

- 버튼을 넣어 즉시 실행 ( 예 : 물 섭취 추가 ), 실행 후 데이터 업데이트로 피드백 ( 스케일 · 블러 등 ).

- 여러 버튼 / 업데이트 동시에 가능 ( 예 : 이퀄라이저 프리셋 ).

- 인터랙션이 없어도 최신 데이터 애니메이션 반영으로 신뢰감 제공 .

- 🧾 스니펫 타입

- Result( 결과 ): 후속 작업 없음 → 하단에 Done만 . ( 예 : 주문 상태 확인 )

- Confirmation( 확인 ): 행동 후 결과가 나오는 흐름 ( 예 : ‘Orderʼ 같이 명확한 동사 버튼). 확인 후 Result로 전환해 완료 인지 .

- 🗣 다이얼로그 ( 음성 ) 다이얼로그는 Siri 가 읽어 주는 보이스 UI로 , 화면을 보지 않아도 의도 전달 · 확인 가능 .

- 다이얼로그 없이도 스니펫만으로 의미가 통하도록 중복 설명은 줄이고 자체 설명력을 확보 .



## ✅ 구현 체크리스트


- 큰 글자 · 간결 정보 , 340pt 이내로 스크롤 회피

- 일관된 마진 / 간격, ContainerRelativeShape 로 크로스플랫폼 대응

- 브랜드 배경 사용 시 고대비 보장 ( 원거리 가독성 테스트 )

- 명확한 동사 버튼과 즉시 상태 업데이트 피드백

- 플로우는 Confirmation → Result 패턴으로 완결

- 다이얼로그는 보조 수단 , 스니펫 단독 이해 가능하게 설계
