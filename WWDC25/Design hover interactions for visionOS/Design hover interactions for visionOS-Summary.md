# Design hover interactions for visionOS

Design hover interactions for visionOS https://developer.apple.com/videos/play/wwdc2025/303/



## ✨ 개요


시선 · 손 제스처 기반의 visionOS 에서 커스텀 Hover 효과, Look to Scroll( 시선 스크롤 ), ** 지속 표시 컨 트롤 (persistent controls)** 로 인터랙션을 더 자연스럽게 만드는 방법을 정리합니다 . 핵심은 “ 사람이 보

는 곳 ” 에 맞춰 빠르게 이해되고 , 과도한 움직임은 피하는 피드백을 설계하는 것 .

👀 기본 원리 (eye + hand) 시선으로 대상 지정 , 손가락 탭으로 선택 .

인터랙티브 요소엔 라운드 형태( 원 / 필 / 라운드 사각 ) 선호 .

요소 간 최소 60pt 간격 확보 ( 고정 스케일 3D 오브젝트에선 약 2.5°, 1m 거리에서 ~4.4cm).

하이라이트 효과는 기본 제공 ( 커스텀 컴포넌트 ·3D 오브젝트에도 적용 ).

🪄 커스텀 Hover 효과 ( 개념 & 제약 ) 시스템이 앱 프로세스 밖에서 Hover 를 처리해 시선 좌표는 앱에 전달되지 않음.

뷰는 기본 상태 / 호버 상태 두 가지를 선언하고 , 시스템이 그 사이를 애니메이션.

- 따라서 애니메이션만 가능하고 , 동작 실행 ( 예 : 다운로드 시작 ) 은 탭 제스처가 필요 .

- ⏱ 애니메이션 유형 (3 가지 )

- Instant: 즉시 작은 정보 노출 ( 예 : 비디오 플레이헤드의 타임스탬프 ).

- Delayed: 짧은 지연 뒤 툴팁 등 추가 정보 노출 ( 빠른 탭을 방해하지 않음 ).

- Ramp: 서서히 힌트 → 의도 확인 시 빠르게 완성 ( 느린 이즈 - 인 뒤 스프링 팝 ). 큰 확장 / 공개에 적합 .

- 🧭 설계 가이드 ( 베스트 프랙티스 )

- 앵커 유지: 제목 등 일부는 고정해 맥락 보존 ( 텍스트가 점프하지 않게 ).

- 작게 · 절제: 툴바 버튼 · 테이블 셀 등 고사용 빈도 UI는 기본 하이라이트 권장 ( 스케일 팝 과다 금지 ).

- 대상은 작게: 큰 이미지 전체에 효과 적용 금지 ( 색 빠짐 , 과도한 모션 ).

- 예상치 못한 움직임 금지: 예 ) 탭 그리드에서 ‘Xʼ 만 시선에 즉시 표시하면 시선이 튀어 오동작 유발 → 반쯤 페이드 → 버튼에 시선 고정 시 완전 표시로 개선 .

- 👁️‍🗨️ Look to Scroll( 시선 스크롤 )

- 옵트인 방식 : 스크롤뷰 가장자리 ( 상 / 하 또는 좌 / 우 ) 를 볼 때 부드럽게 스크롤 .

- 적용 권장: 읽기 / 브라우징 중심 ( 예 : Safari 기사 , TV/ 뮤직 브라우징 ).

- 비권장: 설정처럼 UI 컨트롤 위주 목록 , 패럴랙스 / 커스텀 스크롤 속도 등 비표준 스크롤.

- 디자인 팁: 스크롤뷰가 윈도우 전폭 / 전고를 차지하면 경계가 명확해 예측 가능 . 인셋이면 경계 시각화.

- 🎛 지속 표시 컨트롤 (Persistent controls)

- 비디오 플레이어 등 자동 숨김 UI: 사용자가 보고 있는 동안엔 유지, 콘텐츠로 시선이 돌아오면 숨김.

- 표준 플레이어는 기본 지원 , 커스텀 컨트롤은 직접 채택 필요 . FaceTime/ 마인드풀니스 등 미디어 이 외에서도 유용 .



## 🧪 실무 체크리스트


- 60pt 간격, 라운드 형태 , 기본 하이라이트부터 적용

- 커스텀 효과는 작게 / 앵커 유지 / 과모션 금지

- 정보 공개는 Instant → Delayed → Ramp 순으로 검토

- Look to Scroll 은 읽기 중심 · 주요 콘텐츠에만 옵트인

- 자동 숨김 UI 엔 시선 지속 표시 채택

- 시뮬레이터만으로 판단 금지 → 실제 기기 테스트 & 튜닝 반복
