# Explore prompt design & safety for on-device foundation models

Explore prompt design & safety for on- device foundation models https://developer.apple.com/videos/play/wwdc2025/248/



## ✨ 개요


iOS·iPadOS·macOS·visionOS 에 내장된 Foundation Models 프레임워크 ( 온디바이스 LLM) 를 디자 인 · 엔지니어링 관점에서 잘 쓰는 법과 안전 (guardrails) 설계를 다룹니다 . 모델은 약 30 억 파라미터로 요

약 · 분류 · 작성 등 일상 작업에 적합하나 , 대형 서버 모델 대비 지식 / 추론 한계가 있습니다 .

🧠 온디바이스 LLM 사용 원칙

- 복잡 작업은 쪼개기: 어려운 추론은 단계를 나눠 요청 .

- 수학 / 정확 사실은 비권장: 계산 · 사실성은 코드 / 검증된 데이터로 처리 .

- 코드 생성 지양: 이 모델은 코드에 최적화되어 있지 않음 .

- 지식 최신성 한계: 학습 이후 사건 · 지식은 모를 수 있음 ( 할루시네이션 주의 ).

- Guided generation으로 스키마화된 출력( 숫자 / 배열 / 커스텀 구조 ) 요구 .



## 🧩 프롬프트 베스트 프랙티스


- 한 가지 과업을 명확히: 구체적 · 명령형 톤이 성능 ↑.

- 길이 / 스타일 제어: “3 문장으로 ”, “ 자세히 ” 등 범위 명시 .

- 역할 지정: 톤 · 목소리를 바꾸려면 역할 (“ 셰익스피어풍 여우 ”) 을 지시 .

- 소량 예시 (<5 개 ) 포함으로 출력 형태 고정 .

- 금지 규칙은 ‘DO NOT …ʼ 처럼 강하게 명시 .

- Instructions vs Prompts: 세션 전반의 지침 (instructions) + 매 요청의 프롬프트를 병행 (Xcode #Playground에서 실험 ).

- 🔒 안전 (Guardrails) 설계 입력 · 출력 모두 가드: 프롬프트 · 툴콜 포함 입력과 모델 출력에 시스템 가드레일 적용 .

- 에러 처리 UX: 사용자 주도 기능은 차단 사유를 간단히 안내· 대안 제공 , 자동 기능은 조용히 무시 가 능 .

- 안전 지침을 Instructions 에: 부정적 입력엔 “ 공감적 · 건강한 ” 응답 등 태도 고정 ( 지침은 신뢰 가능 한 소스만, 사용자 입력을 섞지 말 것 ).

- 프롬프트 패턴: 완전 자유 입력 ( 유연성 ↑ 위험 ↑) ↔ 앱 제공 템플릿 / 선택형 프롬프트( 안전 · 일관성 ↑) 를 상황에 맞게 선택 .

- 레이어드 방어 (‘ 스위스 치즈 ʼ): 프레임워크 가드레일 → 지침 → 프롬프트 설계 → 도메인별 추가 완화

- 책( 예 : 알레르기 경고 , 금칙어 , 분류기 ) 순으로 중첩 .



## 🧪 평가 · 테스트 전략


품질 · 안전 데이터셋을 따로 마련 ( 주요 유스케이스 + 실패 유도 프롬프트 포함 ).

자동 실행 파이프라인(CLI/UITest) 으로 정기 돌려 회귀 감시 .

소규모 수동 점검 → 대규모 자동 채점( 다른 LLM 을 채점기로 활용 ).

언해피 경로( 가드레일 오류 , 차단 ) UX 도 함께 검증 .

피드백 수집 · 투명성: 앱 내 사용자 피드백 · 데이터 사용 고지 .



## ✅ 실무 체크리스트


- 과업을 단일 · 구체적으로 정의 , 필요 시 단계 분해

- Guided generation으로 타입 안전 출력 요구

- 지침 (Instructions) 에 안전 · 톤 · 스타일을 고정 , 사용자 입력은 프롬프트로만

- 자유 입력이 필요 없으면 선택형 템플릿 프롬프트 제공

- 가드레일 오류 UI 설계 ( 알림 / 되돌리기 / 대안 액션 )

- 알레르기 / 민감 주제 등 도메인 완화책 적용

- 데이터셋 · 자동화 테스트로 품질 / 안전 회귀 모니터링

- 피드백 채널 및 개인정보 고지 정비

- 필요하시면 현재 기능에 맞춰 지침 템플릿, 선택형 프롬프트 세트, 가드레일 에러 UX 플로우, 테스트 데이터
